# Web probes

Checks worth running on most web apps, after the adapter's own journeys, in this order (each leaves state the next one uses). For a broader UX checklist, `agent-browser skills get dogfood` has an issue taxonomy.

- **Auth and the active context.** Sign up a new fixture account through the UI (the adapter's sign-up steps, e.g. number, code from the dev inbox or menu, profile, company), log out, sign in again, switch company, log out again. A number with an account and one without must get the same code step: deliberate anti-enumeration, never a finding. Each step leaves a clean state: no old context's data on screen, no live session after logging out.
- **Signed-out redirects.** Open a protected page with no session: note the status and the landing URL (the adapter's pattern, e.g. `/auth?next=/app/products`), then sign in and check you return to the page asked for. A redirect that replays a form post at the sign-in page (a 307 or 308 where a 302 or 303 belongs) is a bug; one that lands somewhere unexpected may be the documented redirect working, so check the adapter first.
- **Two tabs, two contexts.** Where a user can switch account, workspace or company, open a second tab, switch it, then save in the first: the save must land where the first tab says it is, and data from the old context still on screen after a switch is the same bug, not a separate finding. This is the highest-value finding on the auth journey.
- **Forms.** Submit empty, too long, mixed scripts and digits (Latin plus each other script the product serves, e.g. Arabic, Hebrew or Persian), and pasted whitespace. Each error sits next to its field and says what to do; the typed values survive the error. Watch for fields the product deliberately does not have (a price on an item whose price lives elsewhere), and, when the adapter names such rules, validation text from a hand-written schema instead of the generated one.
- **Lists.** Create an item, list it, reload, check persistence. Empty state on a fresh account; page to the end; add a row while paging and check nothing repeats or vanishes (keyset paging); filters and search survive a reload when the product says they should. A list the server ordered (for example under a locale collation) must not be re-sorted by the client.
- **Roles.** Repeat a privileged page and its actions as a lower role, and as a non-staff member of a staff-only area: the page and its data must refuse, not just hide the button. Staff areas: create a root item, a child, then add a field to the root and the same key to the child; a key already taken along one line (ancestors, descendants, retired keys all count) must be refused, a retired field must not be editable or re-addable under its old key (append-only trees), and a reload must not leave an old tree on screen.
- **Audit log.** As an admin, after the other journeys, open the audit view and page to the end. An action id that renders raw (`area.thing.added`) because the web has no label for it means the view must still render something sensible (never a crash) and the label is missing (the API can ship an action before its label exists), which is a finding for any new enum value or action id the client has no translation for; a page that loses or repeats a row while paging is the keyset bug; a timestamp in the wrong calendar or numerals for the locale, or formatted at the component instead of through the project's formatter, is a finding. Entries with no actor on purpose (an e-signature provider's callback) are not (adapter).
- **Persistence.** After every save, reload and open the item fresh.
- **Locale and direction.** Switch language on the sign-in page and inside the app: the address behaves as the product says (a locale segment appearing in any URL, or `/en` answering as a page, violates a no-locale-in-URL rule when the adapter says so), the choice (usually a cookie) survives a reload, a new tab and signing out and in, and a soft switch keeps a half-filled form's values. Under right-to-left, icons and margins mirror (a margin that did not mirror used a physical property instead of a logical one); dates, digits and numbers follow the locale (a number or date formatted at the component instead of through the project's i18n formatter is a finding); no untranslated string.
- **Narrow screen.** Re-run the main journeys (auth, and the staff or admin area) at 375 px wide (`agent-browser set viewport 375 812`): no sideways page scroll on the body, every control reachable (none under the fold with no way to scroll to it), tables scroll or stack.
- **Screen vs response.** For anything numeric or listed, compare what the screen shows with what the network returned. Wrong on screen and right in the response is a rendering bug; wrong in the response is an API bug (`api-probes.md`).
- **Every failure, before you record it.** Capture the console errors and the failed or hanging requests at the moment of failure, then reload and reproduce from a fresh load. A hot-reload overlay, a dev-only warning, a timing artifact or a container still starting is not a product bug.
